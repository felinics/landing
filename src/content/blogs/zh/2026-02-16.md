# Memoh 简介：始终在线、容器化的家庭 Agent

## 概述

我们带着一种熟悉的张力进入 2026：模型每个季度都更强，但「Agent 体验」仍然会在上下文、延迟、隐私和真实工作流上断裂。过去一年，我们反复绕着三个问题转：
- Agent 的能力边界到底在哪？
- 长上下文真正值多少？
- 什么样的硬件形态，能让「始终在线的个人 AI」用起来自然？

Memoh 是我们把这些问题做成可交付系统的尝试——不是宣言，而是一套能碰上现实还不散架的东西。

## 故事

时间过得很快。从「这事我记得」到「等一下，我们当时为什么这么决定」，一年就没了。

做产品最烦人的地方在于：大多数进展在发生的时候并不像进展。它只是一连串小选择、没写完的线程、半夜修的 bug，以及偶尔真正对上的瞬间。那种你会靠回椅背想：好，这是真的了。

差不多同一时期，我注意到另一件事：互联网开始更顺了，也更差了。

文字更干净、更长、更礼貌，也更……空。生成的东西有味道：信息密度低，隐喻太多，附和太多，赌注不够。

我也发现自己在这么写。

于是我给自己加了一条约束：说白。保住密度。不要注水。不要躲在风格后面。如果一件事重要，就把它锚在真实的时刻、真实的取舍、真实付过的成本上。

因为 LLM 给不了你的，不是「智能」。是分量。是一个人曾经站在某个时间点、从那个位置写下来的感觉。

那时候我才清楚：我想要的不是「会说话的 AI」。我想要一个能和你一起住的 AI——安静、持续，把上下文攒下来，却不把你的生活变成内容污泥。

手机是第一反应——它个人、强、一直在。但移动 OS 是封闭的：没有 OEM 权限，你能做的是 App，不是环境基础设施。

于是我们去找每个家里已经有的常开节点：路由器（概念上的）。接着是经济上的冲突——路由器级硬件扛不住记忆、RAG、工具和多用户 Agent。设备开始长：更多内存和存储，一块屏，麦克风和喇叭，一点点能带出门的电池，便携形态。

最后它不再是路由器。它变成一个新品类：家庭 Agent 的底座。

## 是什么

Memoh 是容器化的家庭 / 工作室 AI 底座：云端级别的模型能力，配上本地优先的记忆（知识库、RAG/检索、对话历史），控制权留在你这边。

## 为什么

长上下文模型抬高了 Agent 的天花板——但也让「完全本地」变贵，「完全上云」变别扭。人们不想每天重新给 AI 做 briefing，也不想把可长期保存的上下文锁进别人的信息流。容器化让 Memoh 可移植、可复现、适合当成始终在线的基础设施来跑——于是连续性变得便宜、私密、可靠。

## 怎么做

我们把 Memoh 跑成一套容器化栈：存储（文件 / 数据库 / 向量索引）、检索、工具 / 运行时执行、控制面各自隔离。需要前沿能力时，推理走云 API；持久记忆和索引留在本地。设备充当一个始终在线的节点（像路由器，但不是路由器），服务多个用户，边界很清楚：分享是显式的，私有上下文保持私有，所有东西都以版本化容器的方式部署和升级。

## 功能

- **多 Bot 管理**：创建多个机器人；人和 Bot，或 Bot 和 Bot，可以私聊、群聊或协作。

  ![多 Bot 管理](/blogs/2026-02-16/01-multi-bots.png)

- **容器化**：每个 Bot 跑在自己的隔离容器里。Bot 可以在容器内自由执行命令、改文件、访问网络——像拥有自己的电脑。

  ![容器化](/blogs/2026-02-16/02-containerized.png)

- **记忆工程**：每段聊天都进数据库，默认加载最近 24 小时上下文。每一轮对话存成记忆，Bot 可以通过语义检索拿回来。

  ![记忆工程](/blogs/2026-02-16/03-memory-engineering.png)

- **多种平台**：支持 Telegram、飞书等。
- **简单好用**：通过图形界面配置 Bot，以及 Provider、Model、Memory、Channel、MCP、Skills——不用写代码也能搭自己的 AI Bot。
- **计划任务**：用 cron 表达式在指定时间跑命令。
- 还有更多……

## 和 OpenClaw 的比较

我们有一个共同判断：Memoh 和 OpenClaw 都不把 Agent 当成聊天框——我们给 LLM 一块场地：一个能记住、能用工具、能迭代的真实环境。

Memoh 不一样的地方：

- 更轻、更快：按家庭 / 工作室基础设施来做，可以放到边缘设备上
- **默认容器化**：每个 Bot 有隔离容器（文件 / 命令 / 网络 / 任务）
- **混合切分**：推理走云，记忆和索引本地优先
- **多用户优先**：分享和隐私边界是显式的，支持 a2a（Agent2Agent）
- **可持续**：有一支有经验的团队，也有信心继续做下去

## 结语

Memoh 只为一件事而建：始终在线的连续性——AI 一直开着，记忆一直是你的。

前沿推理放在云上，持久上下文留在本地，整套以容器化、始终在线的栈来跑。如果你想要的 Agent 更像家里的基础设施，而不只是一个 App，这就是 Memoh 在下的注。

我们会继续运营，并长期开源 Memoh，把它做成一个能长期产生影响的产品。
